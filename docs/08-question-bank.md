# 08. 학습 — 문제집 / 문제 카드

> 이 문서는 **학습 탭**의 데이터 모델과 동작을 정의한다.
> [07-content-system-future.md](07-content-system-future.md)가 다루는 "개발자 저작 콘텐츠 배포"와는
> **다른 층위**다. 여기는 **사용자가 직접 만드는 문제집**이다.

---

## 0. 이 기능이 기존 원칙을 어떻게 바꾸는가

원래 [00-product-principles.md](00-product-principles.md)는 두 가지를 못박고 있었다.

| 원래 원칙 | 이 기능이 바꾸는 것 |
|---|---|
| 원칙 1: 개발자가 접근 가능한 사용자 데이터 서버 없음 | **공유 기능이 붙으면 바뀐다.** 업로드된 문제집은 개발자 서버에 저장된다 |
| 원칙 3: 커뮤니티·공유 피드 없음 | **바뀐다.** 사용자끼리 문제집을 공유한다 |

**바뀌지 않는 것은 그대로 지킨다.**

- 성적·계획·오답노트 같은 **개인 학습 기록은 여전히 서버로 가지 않는다.** 공유 대상은 문제집뿐이다.
- 문제집을 공유하지 않고 혼자 쓰는 사용자는 **서버와 아무 통신도 하지 않는다.**
- 랭킹·친구·채팅·피드는 여전히 만들지 않는다. 공유는 "문제집을 남이 받아 풀 수 있다"까지다.

### 단계 구분

| 단계 | 범위 | 서버 |
|---|---|---|
| **A (현재)** | 로컬에서 출제하고 로컬에서 푼다. 본인 iCloud로만 동기화 | 불필요 |
| **B (다음)** | 문제집 공유·검색·받기 | 필요 |

**A를 먼저 완성한다.** 모델에는 B에 필요한 필드를 미리 넣되, 값이 비어 있어도 A가 완전히 동작해야 한다.

### B 착수 전 반드시 결정할 것 — 임의로 정하지 않는다

1. **백엔드 선택** — Firebase / Supabase / 자체 서버. 각각 운영 비용과 데이터 소유권이 다르다.
2. **저작권 정책** — 시중 교재·기출문제를 찍어 올리는 것을 어떻게 막을 것인가. 업로드 시 고지만 할지, 신고를 받을지.
3. **검수·신고 체계** — 부적절한 콘텐츠를 누가 어떻게 내리는가. 미성년자 대상 앱이므로 이건 선택이 아니라 필수다.
4. **작성자 식별** — Sign in with Apple 식별자를 쓸지, 별도 표시 이름을 둘지.

## 1. 구조

```
QuestionSet (문제 모음집)
  └─ Question (문제 카드) × N
```

퀴즐렛의 "세트 → 카드"와 같은 구조다. 모음집을 삭제하면 문제도 함께 사라진다 (cascade).

---

## 2. QuestionSet — 문제 모음집

| 속성 | 타입 | 기본값 | 설명 |
|---|---|---|---|
| `title` | `String` | `""` | 모음집 이름 |
| `setDescription` | `String` | `""` | 설명 (선택) |
| `subjectName` | `String` | `""` | 과목 (자유 입력, 마스터 테이블 없음) |
| `createdAt` | `Date` | `Date()` | |
| `updatedAt` | `Date` | `Date()` | 문제를 고칠 때마다 갱신 |
| `questions` | `[Question]?` | `[]` | cascade |

### 공유 대비 필드 (B단계용, A에서는 값이 비어 있음)

| 속성 | 타입 | 기본값 | 설명 |
|---|---|---|---|
| `authorDisplayName` | `String` | `""` | 표시용 작성자 이름. **이메일·실명을 넣지 않는다** |
| `remoteID` | `String?` | `nil` | 서버에 올라간 경우의 식별자. `nil`이면 로컬 전용 |
| `isPublished` | `Bool` | `false` | 공유했는지 |

> `remoteID`가 `nil`인 상태가 정상이며, A단계에서는 항상 `nil`이다.
> 이 필드들 때문에 A단계 동작이 달라지는 곳이 있으면 안 된다.

## 3. Question — 문제 카드

사용자가 요청한 대로 **여러 타입을 하나의 객체로 감당**한다. 타입마다 쓰는 필드가 다르고,
쓰지 않는 필드는 비어 있다.

| 속성 | 타입 | 기본값 | 어느 타입이 쓰나 |
|---|---|---|---|
| `id` | `UUID` | `UUID()` | 전부 |
| `typeRaw` | `String` | `flashcard` | 전부 |
| `orderIndex` | `Int` | `0` | 전부 — 모음집 안 순서 |
| `prompt` | `String` | `""` | 전부 — 문제(앞면) |
| `passageText` | `String` | `""` | 전부 (선택) — 보기 지문 |
| `choices` | `[String]` | `[]` | 객관식 — **최대 5개** |
| `correctChoiceIndex` | `Int?` | `nil` | 객관식 |
| `acceptedAnswers` | `[String]` | `[]` | 플래시카드·빈칸·단답형 — **복수 정답 허용** |
| `explanation` | `String` | `""` | 전부 (선택) — 해설 |
| `hint` | `String` | `""` | 전부 (선택) |
| `questionImageData` | `Data?` | `nil` | 전부 (선택) — 문제 이미지 |
| `explanationImageData` | `Data?` | `nil` | 전부 (선택) — 도움 설명 이미지 |
| `questionSet` | `QuestionSet?` | `nil` | 역참조 |

**이미지는 `@Attribute(.externalStorage)`** 로 저장한다 — 오답노트와 같은 방식이며 CloudKit이 자산으로 동기화한다.
저장 전 리사이즈·압축은 `ImageDownsampler`를 재사용한다.

### 선택지를 배열로 두는 이유

요청은 "선택지1~5"였지만 `[String]` 배열로 둔다. 3지선다도 있고 5지선다도 있는데
`choice1`~`choice5`를 각각 옵셔널로 두면 "중간이 비어 있는" 잘못된 상태가 만들어질 수 있다.
배열이면 **개수 자체가 곧 선택지 수**여서 그런 상태가 생기지 않는다. 최대 5개 제한은 UI에서 건다.

## 4. QuestionType — 문제 타입

| 타입 | 한국어 | 푸는 방식 | 정답 저장 위치 |
|---|---|---|---|
| `flashcard` | 카드 (뜻 맞추기) | 앞면 보고 떠올린 뒤 뒤집어 확인 | `acceptedAnswers[0]`을 뒷면으로 표시 |
| `multipleChoice` | 객관식 | 선택지 탭 | `correctChoiceIndex` |
| `fillInBlank` | 빈칸 채우기 | 빈칸에 입력 | `acceptedAnswers` |
| `shortAnswer` | 단답형 | 자유 입력 | `acceptedAnswers` |

### 빈칸 표기

`prompt` 안에 `____`(밑줄 4개 이상)를 넣으면 빈칸으로 본다. 앱이 빈칸 위치를 추측하지 않는다 —
출제자가 명시적으로 표시한다.

## 5. 채점 규칙 — `QuestionGrader`

순수 Swift로 구현한다. SwiftData·SwiftUI를 import하지 않는다.

### 객관식

`선택 인덱스 == correctChoiceIndex`. `correctChoiceIndex`가 `nil`이면 **채점하지 않는다**
(출제자가 정답을 지정하지 않은 경우 — 골라보기만 한다).

### 단답형 / 빈칸

정규화 후 `acceptedAnswers` 중 하나와 일치하면 정답.

**정규화 규칙** (순서대로):
1. 앞뒤 공백 제거
2. 연속 공백을 하나로
3. 대소문자 무시 (영어)

**하지 않는 것**: 오타 교정, 유사도 판정, 부분 점수. 앱이 정답을 추측하지 않는다.
"apple"과 "Apple"은 같게 보지만, "aple"은 오답이다.

복수 정답은 출제자가 직접 여러 개 입력한다 (예: "사과", "apple").

### 플래시카드

**채점하지 않는다.** 학생이 스스로 "알았음/몰랐음"을 누른다 — 오답노트 복습과 같은 방식이다.

## 6. 학습 세션

한 모음집을 처음부터 끝까지 푼다.

- 문제 순서는 `orderIndex`를 따른다. 섞기는 선택 옵션으로 둔다.
- **즉시 채점**한다. 답을 내면 바로 맞았는지 보여주고 해설을 편다.
- 세션이 끝나면 맞은 개수를 보여준다. **틀린 문제만 다시 풀기**를 제공한다.
- 오답을 빨간색으로 강조하지 않는다 ([04](04-ui-spec.md) 색상 원칙 그대로).
- 점수·랭킹·스트릭을 만들지 않는다. 압박 장치를 넣지 않는 것이 이 앱의 방침이다.

세션 결과는 **저장하지 않는다.** 학습 기록을 쌓아 통계를 내는 것은 별도 결정이 필요한 확장이다.

## 7. 오답노트와의 관계

둘은 **다른 것**이다.

| | 오답노트 | 문제집 |
|---|---|---|
| 목적 | 내가 틀린 것을 기록 | 문제를 만들어 반복 학습 |
| 출처 | 실제 시험·문제집에서 틀린 문제 | 직접 출제 |
| 복습 | 스페이스드 리피티션 (Leitner) | 세션 단위로 처음부터 |
| 소속 | 과목(내신/모의고사) 하위 | 독립적인 모음집 |

나중에 "오답노트를 문제집으로 보내기"를 붙일 수 있지만, 지금은 연결하지 않는다.
