# 07. 콘텐츠 시스템 (장기 로드맵)

> ## ⚠️ 이 문서의 내용은 **1차 개발 범위에서 구현하지 않는다.**
> 여기 적힌 엔티티나 다운로드 파이프라인을 코드로 만들지 않는다.
> 1차 데이터 모델이 이 확장을 **방해하지 않도록** 하는 것이 목적이다.

---

## 1. 왜 이것이 "자체 서버 없음" 원칙과 충돌하지 않는가

두 가지가 서로 다른 층위이기 때문이다.

| | 개인 데이터 | 저작 콘텐츠 |
|---|---|---|
| 무엇 | 성적·계획·오답노트 | 단어장·듣기·문제은행 |
| 누가 만드나 | 사용자 | 개발자 본인 |
| 방향 | 기기 안에 머묾 | 개발자 → 모든 사용자 (읽기 전용) |
| 저장소 | SwiftData + CloudKit Private | 정적 캐시 (별도 컨테이너) |
| 인증 | 불필요 (로컬) / Apple ID (동기화) | **불필요** — 공개 자료 |
| 개발자 접근 | **불가능** | 원본을 소유 (당연) |

원칙 1이 금지하는 것은 **사용자 데이터를 개발자가 수집하는 것**이다. 개발자가 만든 콘텐츠를 배포하는 것은 여기 해당하지 않는다.

**이 구분이 흐려지면 원칙이 지켜지는지 판단할 수 없게 된다.** 그래서 저장소를 코드 레벨에서 분리한다.

---

## 2. 콘텐츠 유형

| 유형 | 내용 |
|---|---|
| 오늘의 단어 | 매일 노출되는 영단어 카드 (단어, 뜻, 예문, 발음) |
| 영어듣기 | 오디오 파일 + 스크립트 + 문제 |
| 유형별 문제은행 | 과목/유형별 문제 세트 |

**전부 개발자 본인이 직접 제작한 것만 담는다.** 시중 교재·기출문제 원문·제3자 저작물은 절대 포함하지 않는다.

---

## 3. 배포 아키텍처

```
개발자 저작 (JSON/CSV)
      ↓ 수동 업로드
정적 파일 호스팅 (Cloudflare R2 / S3+CloudFront)
      ├─ manifest.json  (버전드)
      └─ packs/*.json, audio/*.m4a
      ↓ 앱이 주기적으로 매니페스트 확인
델타 다운로드 (새 팩만) → 로컬 콘텐츠 캐시
```

### 원칙

- **버전드 매니페스트**: 앱이 매니페스트를 먼저 받아 로컬 버전과 비교하고, 바뀐 팩만 내려받는다. 전체 재다운로드하지 않는다.
- **앱스토어 재심사 없이 콘텐츠 갱신 가능**해야 한다. 그래서 콘텐츠를 번들에 넣지 않는다.
- **인증 없음.** 모든 사용자에게 동일하게 배포되는 공개 자료다. 사용자 식별자를 서버에 보내지 않는다.
- **업로드 방향 없음.** 앱은 콘텐츠 서버에 아무것도 쓰지 않는다. 다운로드 전용이다.
- 콘텐츠 제작 도구(CMS)는 **이 앱의 범위가 아니다.** 개발자가 별도로 JSON/CSV를 만들어 올린다.

---

## 4. 데이터 모델 확장 여지 (구현하지 않음)

```
ContentPack
  id, version, type(vocabulary/listening/questionBank), releaseDate

VocabularyItem
  id, contentPackID, word, meaning, exampleSentence, audioURL?

ListeningItem
  id, contentPackID, audioURL, script, questions

QuestionBankItem
  id, contentPackID, subject, questionType, questionText, choices, answer, explanation
```

### 1차 모델이 지켜야 할 것 — 이것만 지금 유효하다

사용자가 나중에 문제은행 문항을 오답노트에 스크랩하는 기능이 생기더라도:

- **콘텐츠 원본을 사용자 데이터 저장소로 복제하지 않는다.** `WrongAnswerNote`가 `contentItemID` 같은 **참조만** 갖는다.
- 참조는 옵셔널이어야 하고, 콘텐츠 팩이 삭제되어도 사용자 기록이 깨지지 않아야 한다.
- 두 저장소는 서로 다른 `ModelContainer`를 쓴다. 같은 컨테이너에 섞지 않는다.

현재 `WrongAnswerNote`에는 콘텐츠 참조 필드가 **없다.** 필요해지는 시점에 옵셔널 `String?` 하나를 추가하면 되며, 이는 CloudKit 스키마 제약과도 충돌하지 않는다. **지금 미리 추가하지 않는다.**

---

## 5. 수익화 (장기, 1차 제외)

콘텐츠 팩 일부를 StoreKit 인앱결제로 유료화하는 것을 장기적으로 고려할 수 있다.

- 1차 범위에서 **완전히 제외**한다. StoreKit을 링크하지 않는다.
- 도입하더라도 **개인 데이터는 결제와 무관**해야 한다. 성적 기능에 결제 장벽을 두지 않는다.

---

## 6. 이 문서를 다시 열어야 할 때

1차 개발 9단계가 전부 끝나고, 사용자가 명시적으로 콘텐츠 시스템 착수를 요청했을 때. 그 전에는 이 문서의 내용을 코드로 옮기지 않는다.

착수 시점에 먼저 결정해야 할 것:
- 호스팅 제공자와 비용 구조
- 매니페스트 스키마 확정
- 오디오 파일 포맷·용량 정책
- 콘텐츠 저작 워크플로 (스프레드시트 → JSON 변환 도구)
- 오프라인 정책 (다운로드한 팩은 영구 보관인가, 캐시 만료가 있는가)
