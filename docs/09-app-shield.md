# 09. 앱 차단 (집중 모드)

> ## ⚠️ 이 문서는 **설계만** 담는다. 아직 구현하지 않는다.
> Apple의 Family Controls entitlement 승인이 선행 조건이며, 2026년 7월 현재 심사가 지연되고 있다.
> 선행 조건은 §6에 정리했다.

학생이 스스로 정한 시간 동안, 스스로 고른 앱을 잠가두는 기능이다.

---

## 0. 이 기능이 원칙과 부딪히는 지점

[00-product-principles.md](00-product-principles.md)는 **압박 장치를 넣지 않는다**고 정해두었다.
그래서 스트릭·랭킹·정답률 경쟁을 전부 뺐다.

**"할 일을 못 끝내면 폰이 안 풀린다"는 지금까지 만든 어떤 것보다 강한 압박이다.**

그럼에도 만드는 이유는, 이것이 **남이 나에게 가하는 압박이 아니라 내가 나에게 거는 약속**이기 때문이다.
스트릭은 앱이 사용자를 붙잡아두려고 만드는 장치지만, 집중 모드는 사용자가 스스로 요청하는 장치다.

**그래서 다음을 반드시 지킨다.**

1. **사용자가 켜야만 동작한다.** 기본값은 꺼짐이며, 온보딩에서 권하지 않는다.
2. **강도를 사용자가 고른다** (→ §4). 앱이 대신 정하지 않는다.
3. **탈출구가 항상 있다** (→ §5). 어떤 강도에서도 빠져나올 수 있다.
4. **실패를 꾸짖지 않는다.** 차단을 해제해도 기록에 남기거나 불이익을 주지 않는다.
5. **부모가 자녀를 통제하는 용도로 만들지 않는다.** 이 앱은 학생 본인의 도구다.

## 1. 기술 구조 — Screen Time API

Apple이 제공하는 세 프레임워크를 함께 쓴다.

| 프레임워크 | 역할 |
|---|---|
| `FamilyControls` | 권한 요청, 차단할 앱을 사용자가 고르는 피커 |
| `ManagedSettings` | 실제 차단을 걸고 푸는 곳 |
| `DeviceActivity` | 시간대 스케줄, 시작·종료 콜백 |

### 앱 목록을 우리가 알 수 없다 — 그리고 알 필요도 없다

**iOS는 설치된 앱 목록을 앱에게 알려주지 않는다.** 이건 우회할 방법이 없고, 우회하려 해서도 안 된다.

대신 이렇게 동작한다.

```
사용자가 FamilyActivityPicker(애플이 만든 화면)를 연다
        ↓
사용자가 차단할 앱·카테고리를 고른다
        ↓
앱은 ApplicationToken / ActivityCategoryToken 을 받는다
   ← 이 토큰으로는 "무슨 앱인지" 알 수 없다 (불투명)
        ↓
토큰을 ManagedSettingsStore.shield.applications 에 넣는다
        ↓
iOS가 차단한다
```

**결과적으로 우리는 학생이 어떤 앱을 쓰는지 끝까지 모른다.** 앱 목록을 따로 받아두거나 관리할 필요가 없고,
[프라이버시 원칙](00-product-principles.md)과도 어긋나지 않는다.

> 토큰은 기기·앱 단위로만 유효하다. 서버로 보내거나 백업에 넣지 않는다.
> 기기를 바꾸면 다시 골라야 하며, 이는 정상 동작이다.

### 필요한 앱 익스텐션 2개

| 익스텐션 | 역할 | 없으면 |
|---|---|---|
| `DeviceActivityMonitor` | 스케줄 시작·종료 시점에 차단을 켜고 끈다 | 시간대별 차단이 동작하지 않는다 |
| `ShieldConfiguration` | 차단 화면의 문구·색을 우리 앱에 맞게 바꾼다 | 애플 기본 화면이 나온다 (동작은 함) |

두 익스텐션 모두 **각각 별도로 entitlement 승인**을 받아야 한다.

## 2. 차단을 거는 두 가지 방식

### 2-1. 시간대 기반

플래너의 시간표와 연결하지 않고 **별도 스케줄**로 둔다.
학교 수업 시간에 자동으로 잠그면 학생이 통제권을 잃는 느낌을 받는다.

```
집중 시간대 (사용자가 직접 만든다)
  - 요일 (복수 선택)
  - 시작 / 종료 시각
  - 차단할 앱 묶음
```

`DeviceActivitySchedule`로 등록하고, `DeviceActivityMonitor`의
`intervalDidStart` / `intervalDidEnd`에서 차단을 켜고 끈다.

### 2-2. 할 일 달성 기반

오늘 할 일 완료율이 기준을 넘으면 차단이 풀린다.

```
목표 달성률 (기본 80%, 사용자가 조절)
        ↓
오늘 할 일 완료율 >= 목표  →  차단 해제
```

**규칙**

- 완료율은 **오늘 날짜의 `PlanItem`만** 센다. 지난 할 일을 끌고 오지 않는다.
- 오늘 할 일이 **0개면 차단을 걸지 않는다.** 할 일을 안 만든 것이 잠길 이유가 되면 안 된다.
- 한 번 해제되면 **그날은 다시 잠기지 않는다.** 할 일을 지워서 완료율이 떨어져도 마찬가지다.
  (해제를 되돌리면 사용자가 앱을 신뢰할 수 없게 된다.)
- 자정에 초기화된다.

## 3. 데이터 모델 (초안)

```
FocusSchedule (집중 시간대)          — SwiftData
  title: String                      "자습 시간"
  weekdays: [Int]                    Calendar 컨벤션 (1=일)
  startTime / endTime: Date          시·분만 의미 있음
  isEnabled: Bool
  strengthRaw: String                → §4
  createdAt: Date

FocusSettings (전역 설정)            — @AppStorage
  isShieldEnabled: Bool = false      기본 꺼짐
  unlockByTaskCompletion: Bool       할 일 연동 여부
  requiredCompletionRate: Double     기본 0.8
```

**차단 대상 앱 토큰은 SwiftData에 넣지 않는다.**
`FamilyActivitySelection`은 별도로 직렬화해 `UserDefaults`(앱 그룹)에 저장한다 —
익스텐션과 공유해야 하고, CloudKit으로 동기화하면 안 되는 값이기 때문이다.

> **백업 제외**: 앱 토큰은 [JSON 백업](06-sync-and-backup.md)에 포함하지 않는다.
> 다른 기기에서 의미가 없는 값이다.

## 4. 강도 3단계 — 사용자가 고른다

| 강도 | 차단 화면에서 | 쓰임새 |
|---|---|---|
| **부드럽게** | "그래도 열기"를 바로 누를 수 있다 | 습관을 만드는 마찰 장치. 무의식적으로 여는 것만 막는다 |
| **보통** (기본) | 15초 기다린 뒤 열 수 있다 | 충동을 한 번 끊는다 |
| **엄격하게** | 시간이 끝나거나 할 일을 채워야 열린다 | 시험 기간처럼 스스로 강하게 묶고 싶을 때 |

**기본값은 "보통"이다.** 처음 켜는 사용자에게 "엄격하게"를 기본으로 주지 않는다.

강도는 **집중 시간대마다 따로** 정한다. 평일 자습은 엄격하게, 주말은 부드럽게 같은 설정이 가능하다.

## 5. 탈출구 — 어떤 강도에서도 반드시 있다

미성년자가 쓰는 앱이다. **폰이 잠겨서 곤란해지는 상황을 절대 만들지 않는다.**

### 5-1. 애초에 차단하지 않는 것

`FamilyActivityPicker`에서 사용자가 무엇을 고르든, 다음은 **차단 목록에 넣지 않는다.**

- 전화 / 메시지 / 긴급 통화
- 설정
- 지도

> iOS가 전화·긴급통화를 시스템 차원에서 보호하지만, 우리 쪽에서도 안전 목록을 유지한다.
> **이 목록은 사용자가 해제할 수 없다.**

### 5-2. 긴급 해제

강도가 "엄격하게"여도 **긴급 해제**를 항상 제공한다.

- 차단 화면과 앱 안 두 곳 모두에서 접근할 수 있다
- 확인 한 번을 거치되, 이유를 묻거나 캐묻지 않는다
- **해제해도 기록·통계·불이익이 없다.** "이번 주 3번 포기함" 같은 표시를 만들지 않는다

### 5-3. 전체 끄기

설정에서 집중 모드 전체를 한 번에 끌 수 있다. 이 스위치는 어떤 강도에서도 잠기지 않는다.

## 6. 선행 조건 — 이것이 해결되어야 착수한다

| # | 조건 | 현재 상태 |
|---|---|---|
| 1 | 유료 Apple Developer Program 멤버십 | **미충족** — 무료 팀(softium)으로는 entitlement 신청 불가 |
| 2 | Family Controls entitlement (개발용) | 미신청 |
| 3 | Family Controls entitlement (배포용) | 미신청 — **별도 심사이며 2026년 현재 지연** |
| 4 | 익스텐션 2개 각각의 entitlement | 미신청 |

### 신청 시 유의할 것

- **개발용과 배포용은 별개다.** 개발용이 나와도 TestFlight·App Store에 올릴 수 없다.
- 신청서에 **디지털 웰빙 목적**을 분명히 적어야 한다. 애플은 용도를 심사한다.
- 익스텐션 승인이 **본체 승인 후 2주 이상** 더 걸린다는 보고가 있다.
- 승인 전에는 실기기에서도 동작을 확인할 수 없다.

**심사가 오래 걸리므로, 다른 기능을 진행하면서 신청을 먼저 넣어두는 편이 낫다.**

## 7. 이번 범위에서 하지 않는 것

- **부모 통제(자녀 계정) 모드** — 이 앱은 학생 본인의 도구다. `.child` 권한을 쓰지 않는다
- **사용 시간 통계·리포트** — 어떤 앱을 얼마나 썼는지 수집하지 않는다. 토큰이 불투명해 애초에 불가능하고, 가능해도 하지 않는다
- **차단 회피 시도 감지·신고** — 학생을 감시하지 않는다
- **차단 실패 기록** — §5-2 참조
- **웹 도메인 차단** — 1차 범위 밖
