# 00. 제품 원칙

## 한 줄 정의

한국 고등학생(입시 준비생)을 위한 **로컬 우선 자기관리 앱**.
학교·학원 시간표, 일/주/월간 계획, 과목별 목표 대비 실제 성적, 내신(5등급제)과 모의고사(9등급제)를 분리 관리하고, 오답노트를 온디바이스 OCR로 처리한다.

## 대상 사용자

- 주 사용자: 고1~고3 (2025년 입학생부터 5등급제 적용 → 5등급제가 기본값)
- 부 사용자: 2024년 이전 입학생 (9등급제) — 제도 전환기이므로 두 제도를 모두 지원한다
- 사용 맥락: 하루에 여러 번, 짧게. 등하교·쉬는 시간·자습 시작 직전. **한 번에 오래 쓰는 앱이 아니다.**

이 사용 맥락이 UI 결정의 기준이다. 화면당 핵심 동작은 1~2개, 자주 하는 입력은 3탭 이내에 끝나야 한다.

## 절대 원칙 (Non-negotiable)

### 1. 개인 학습 기록은 서버로 가지 않는다

성적·오답노트·계획 같은 **개인 데이터**를 개발자가 접근 가능한 서버·DB에 수집하지 않는다.

이는 "동기화를 안 한다"는 뜻이 아니라 **"계정 인프라를 애플이 대신 운영하게 한다"**는 뜻이다. Sign in with Apple + CloudKit Private Database를 쓰면 데이터는 사용자 본인의 iCloud 계정 아래 저장되고, 개발자에게는 그것을 열람할 서버도 권한도 없다.

> **2026-07 변경**: 학습 탭의 **문제집 공유**(→ [08](08-question-bank.md))가 도입되면서 이 원칙의 범위가 좁아졌다.
> 공유 대상은 **사용자가 직접 만든 문제집뿐**이며, 성적·오답노트·계획은 **여전히 서버로 가지 않는다.**
> 문제집을 공유하지 않는 사용자는 서버와 아무 통신도 하지 않는다.

> **2026-07 추가 — 시스템 캘린더 읽기·쓰기**: 플래너 월간 보기가 EventKit으로 기기의
> 캘린더 일정을 읽고 쓴다. 이 원칙을 어기지 않는다 — 일정은 **개발자 서버로 가지 않고**
> 기기의 캘린더에만 오간다. iCloud·Google 등 계정 동기화는 iOS가 담당하며 앱은
> CalDAV를 직접 다루지 않는다.
>
> 다만 **권한이 하나 늘고, 앱이 사용자의 개인 일정 전체를 읽게 된다**는 점은 분명히 해둔다.
> 그래서 월간 보기에 들어갈 때만 권한을 요청하고, 거부해도 다른 보기(일간·주간)는 그대로
> 동작한다. 거부한 경우 무엇이 막혔는지와 어디서 켜는지를 화면에 안내한다.
>
> **어떤 보기가 무엇을 다루는지 헷갈리면 안 된다** — 월간은 캘린더 일정, 일간·주간은
> 할 일과 시간표다. 서로 다른 저장소의 다른 데이터다.

### 2. 로컬 우선

모든 개인 데이터는 기기 로컬 SwiftData에 저장된다. **로그인하지 않아도 앱의 모든 핵심 기능이 100% 동작해야 한다.** 동기화는 순수하게 선택 기능이다.

로그인 화면을 앱 첫 진입에 두지 않는다. 온보딩에도 넣지 않는다. 설정 탭 안의 "동기화 켜기" 한 줄로만 노출한다.

### 3. 성적으로 남과 비교당하지 않는다

**랭킹, 점수 경쟁, 친구 추가, 채팅, 성적 피드를 만들지 않는다.**
성적은 비교당하면 해로운 데이터다. 내 성적 화면에는 다른 사람이 등장하지 않는다.

> **2026-07 변경**: 원래 문구는 "커뮤니티/소셜 기능 없음"이었으나, 학습 탭의 **문제집 공유**가
> 도입되면서 다시 썼다. 공유되는 것은 **문제집(학습 자료)** 이지 **성적이 아니다.**
> 공유 범위는 "남이 만든 문제집을 받아 푼다"까지이며, 랭킹·스트릭·정답률 경쟁은 여전히 만들지 않는다.
> 상세와 미결정 사항은 → [08](08-question-bank.md) §0

> **2026-07 예외 (개발자 전용)**: `개발자` 탭의 팀 메신저(→ [10](10-developer-chat.md))는
> "채팅을 만들지 않는다"의 예외다. **학생이 아니라 이 앱을 만드는 개발자 팀끼리**
> 개발 기간에만 쓰는 내부 도구이며, 화면·로직은 전부 `#if DEBUG`로 감싸 Release
> 바이너리에서 빠지도록 만든다(오답노트 샘플 데이터 시더와 같은 방식, `strings`로 검증).
> 다만 이 기능이 쓰는 서드파티 패키지(supabase-swift)는 Xcode 구조상 설정만으로는
> 빌드 구성별로 링크를 뗄 수 없어 Release 아카이브에도 **정적으로는 포함된다** —
> 호출되지 않을 뿐이다. App Store 제출 직전에는 이 패키지 의존성 자체를
> `project.yml`에서 제거하는 것을 출시 체크리스트 항목으로 둔다.

**압박 장치를 만들지 않는다** — 스트릭, 연속 기록, "며칠째 안 함" 같은 표시를 넣지 않는다.

> **예외 하나**: 앱 차단(집중 모드, → [09](09-app-shield.md))은 압박처럼 보이지만
> **남이 거는 압박이 아니라 사용자가 자신에게 거는 약속**이라 허용한다.
> 대신 강도를 사용자가 고르고, 어떤 강도에서도 탈출구가 있으며,
> **포기해도 기록에 남기지 않는다**는 조건을 지킨다.

### 4. 광고 없음 / 인앱결제 없음 (1차)

### 5. 제3자 저작물 없음

시중 교재, 기출문제 원문, 가사 등을 포함하지 않는다. 장기 콘텐츠 시스템(→ [07](07-content-system-future.md))에도 개발자 본인 저작물만 담는다.

### 6. 추정을 단정하지 않는다

모의고사 등급컷은 시행마다 다르고 공식 발표 전에는 추정치일 뿐이다. **앱이 등급을 자동 산출하지 않는다** — 사용자가 직접 입력한다.

통계적 추정치를 보조로 보여주는 경우(예: 표준편차 기반 예상 등급)는 반드시 "추정" 레이블과 근거를 함께 표시한다. 근거 없는 숫자를 확정처럼 보여주는 것은 이 앱에서 버그다.

### 7. 과목은 제안하되 단정하지 않는다

고교학점제로 학생마다 이수 과목이 다르고 교육과정도 계속 바뀐다.
**앱이 "이 학생은 이 과목을 듣는다"고 단정하지 않는다.**

> **2026-07 개정**: 원래 문구는 "과목 목록을 내장하지 않는다"였다.
> 모든 과목을 매번 타이핑해야 하는 것이 실제로 큰 불편이라, **무엇이 전국 공통이고
> 무엇이 학교마다 다른지**를 기준으로 다시 나눴다.

| 구분 | 근거 | 앱의 태도 |
|---|---|---|
| **고1 공통과목** | 국가 교육과정이 정함. 전국 공통 | **프리셋으로 제공.** 학기 생성 시 함께 넣을지 선택 |
| **석차등급 산출 여부** | 교육부 훈령. 학교 재량 아님 | **제안.** 과목명으로 추정해 채워주되 사용자가 바꿀 수 있다 |
| **2·3학년 선택과목** | 학교·학생마다 다름 | **프리셋 아님.** 이름 자동완성 후보로만 제공 |

**지켜야 할 선**

- 프리셋으로 넣은 값도 **전부 수정·삭제 가능**해야 한다. 잠긴 과목을 만들지 않는다.
- 목록에 없는 과목을 **직접 입력하는 경로가 항상 열려 있어야** 한다.
- 추정한 평가 방식을 확정처럼 보여주지 않는다 (원칙 6과 같은 태도).
- 데이터 출처와 불확실한 부분을 코드 주석에 남긴다. 2015 개정 이수단위처럼
  2차 출처로만 확인된 값은 UI에서 그 사실을 알린다.

데이터와 출처 → [`Utilities/CurriculumPreset.swift`](../Studion/Utilities/CurriculumPreset.swift)

## 디자인 철학

**Apple HIG를 따른다.** 구체적으로 이 앱에서 그 뜻은:

- 화면당 핵심 동작 1~2개. 툴바에 버튼 5개를 늘어놓지 않는다.
- 내비게이션 깊이 **3뎁스 이내** (기록 탭 → 과목 리스트 → 과목 상세 → 오답노트)
- 학생에게 보이는 탭은 **4개로 고정**(플래너/학습/기록/설정). 늘리지 않는다.

> **2026-07 변경**: 탭이 다섯 개가 됐다 — 캘린더 / 오늘 할 일 / 학습 / 기록 / 설정.
> 플래너 하나에 캘린더와 할 일을 함께 담았더니 **서로 다른 데이터**(기기 캘린더 일정 vs
> 앱의 할 일·시간표)가 한 탭에 섞여 무엇을 보고 있는지 헷갈렸다. 데이터가 다르면 탭도
> 나누는 편이 낫다고 판단해 원칙을 고쳤다.
>
> 팀 메신저는 탭이 아니라 **설정 > 개발자 도구** 안에 두고 DEBUG 빌드에서만 컴파일한다
> (→ [10](10-developer-chat.md)). 탭바에 있으면 학생이 쓰는 기능처럼 보인다.
- "기능이 많아 보이는 것"을 목표로 하지 않는다. 안 쓰는 기능은 부채다.
- 애니메이션 절제. 시스템 기본 전환을 쓰고 커스텀 트랜지션을 남발하지 않는다.

### 색채 원칙 — 실패를 색으로 강조하지 않는다

브랜드 accent color는 **`#FF212B`** (레드)다. 이 빨강은 **강조·선택·브랜드 정체성**을 위한 색이며, 경고나 실패를 뜻하지 않는다.

학생 대상 앱이므로 **목표 미달을 부정적 색채로 표시하지 않는다.**

- 목표 달성: 그린 계열 (절제된 톤)
- 목표 미달: **뉴트럴 그레이** — 빨강을 쓰지 않는다
- 강조·선택·월간 완료율 히트맵: accent color 농도
- 파괴적 동작(삭제 확인): **색이 아니라 휴지통 아이콘과 명시적 확인 다이얼로그로 구분**한다

> accent가 빨강이므로 "빨강 = 위험"이라는 관습을 색만으로 전달할 수 없다.
> 파괴적 동작은 아이콘·문구·확인 절차로 드러내며, 이는 색상에만 의존하지 않는 접근성 원칙과도 맞는다.

## 의사결정 기준 (막혔을 때 이 순서로 판단)

1. 이 결정이 **원칙 1~7 중 하나를 위반하는가?** → 위반하면 그 방향은 버린다.
2. **학생이 불안해지는가?** (비교, 경고색, 부정적 피드백) → 그러면 버린다.
3. **화면당 동작이 3개 이상 되는가?** → 쪼개거나 덜어낸다.
4. **사용자가 직접 입력해야 정확한 값을 앱이 추측하고 있는가?** → 입력받는다.
5. 그래도 모호하면 **사용자에게 묻는다.** 임의로 정하고 넘어가지 않는다.
