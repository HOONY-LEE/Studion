# 단계별 실행 스펙 — 배치 실행 프로토콜

각 `stage-N.md`는 **그 파일 하나만 읽고도 독립 실행 가능**하도록 작성되어 있다.
에이전트에게 넘길 때는 `CLAUDE.md` + 해당 `stage-N.md` + 스펙이 참조하는 설계 문서만 주면 된다.

---

## 단계 목록과 의존 관계

```
1 스캐폴딩 ✅ 완료
    ↓
2 내비게이션 셸 ────────────────────┐
    ↓                              │
3 내신 (등급 로직 + UI)             │
    ↓                              │
4 모의고사 + 목표 진척              │  5 플래너는 2단계 직후 착수 가능
    ↓                              │  (3·4와 독립)
    └──────────┬───────────────────┘
               ↓
6 오답노트 + OCR   (4단계의 과목 상세 화면에 오답노트 섹션을 얹는다)
               ↓
7 CloudKit 동기화  (전 모델 확정 후)
               ↓
8 설정 (테마·언어·백업)
               ↓
9 온보딩 + 빈 상태 + 마무리
```

**기본은 순차 실행(2→3→…→9)이다.** 5단계만 3·4단계와 병렬 가능하지만, 같은 파일을 건드리지 않는지 확인한 뒤에만 그렇게 한다.

## 스펙 문서의 공통 구조

모든 `stage-N.md`는 아래 순서를 따른다. 이 구조를 바꾸지 않는다.

```
1. 목표          — 한 문단. 이 단계가 끝나면 무엇이 가능해지는가
2. 선행 조건     — 시작 전 확인할 것
3. 참조 문서     — 읽어야 할 설계 문서 섹션 (링크)
4. 만들 파일     — 신규/수정 파일 목록. 여기 없는 파일을 건드리지 않는다
5. 구현 명세     — 항목별 요구사항
6. 수용 기준     — 체크리스트. 항목별로 자기 점검한다
7. 검증 절차     — 실제 실행할 커맨드
8. 범위 밖       — 이 단계에서 하지 않을 것 (다음 단계 침범 방지)
9. 막히면        — 사용자에게 물어야 할 지점
```

## 배치 실행 규칙

### 1. 경계를 넘지 않는다

각 스펙의 **"만들 파일"에 없는 파일을 만들거나 고치지 않는다.**
다음 단계 것을 미리 구현하지 않는다. "어차피 나중에 필요하니까"는 이 프로젝트에서 하지 않는다.

### 2. 완료 정의를 지킨다

`CLAUDE.md` §5의 완료 정의를 **모두** 만족해야 완료다.

1. `xcodegen generate` 후 빌드 성공 (신규 경고 0)
2. 테스트 전체 통과
3. 시뮬레이터 스크린샷으로 화면 확인 (라이트 + **다크모드 둘 다**)
4. 수용 기준 체크리스트 항목별 자기 점검
5. 원칙 위반 없음

**빌드나 테스트가 실패한 채로 완료 보고하지 않는다.**

### 3. 원칙 체크 (매 단계 필수)

- [ ] `URLSession`·네트워크 코드를 추가하지 않았다 (CloudKit 제외)
- [ ] 서드파티 의존성을 추가하지 않았다
- [ ] 하드코딩된 과목 목록·등급컷 데이터를 넣지 않았다
- [ ] 추정치에 "추정" 레이블을 붙였다
- [ ] 목표 미달을 빨간색으로 표시하지 않았다
- [ ] 문자열을 하드코딩하지 않았다 (로컬라이징 가능한 형태)
- [ ] 고정 폰트 크기·고정 width/height를 쓰지 않았다
- [ ] `Utilities/`에 SwiftData·SwiftUI를 import하지 않았다
- [ ] 모델을 건드렸다면 CloudKit 제약을 유지했다 ([02](../02-data-model.md) 참조)

### 4. 모호하면 멈춘다

스펙이 모호하거나 설계 문서와 충돌하면 **임의로 정하고 넘어가지 않는다.**
그 사실을 기록하고 사용자에게 묻는다. 각 스펙의 "막히면" 섹션에 예상 질문 지점이 적혀 있다.

### 5. 커밋

단계 단위로 커밋한다. 메시지: `[stage-N] 요약` (한국어).
사용자가 요청하지 않았다면 push하지 않는다.

## 에이전트에게 배치로 넘기는 방법

### 단일 단계

```
docs/tasks/stage-3.md 를 읽고 그 스펙대로 구현해줘.
CLAUDE.md의 작업 규칙과 완료 정의를 지키고,
수용 기준을 항목별로 자기 점검한 결과를 보고해줘.
```

### 연속 실행

```
docs/tasks/stage-3.md 부터 stage-5.md 까지 순서대로 진행해줘.
각 단계마다 CLAUDE.md의 완료 정의(빌드·테스트·스크린샷·수용기준)를 만족해야
다음 단계로 넘어간다. 한 단계라도 실패하면 거기서 멈추고 보고해줘.
```

### 병렬 (5단계만 해당)

5단계는 3·4단계와 파일이 겹치지 않는다. 병렬로 돌릴 경우:
- 서로 다른 워크트리에서 작업시킨다
- `project.yml`은 양쪽이 모두 건드리므로 **머지 시 충돌을 확인**한다
